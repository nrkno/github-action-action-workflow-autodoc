# Github action for updating docs automaticly

A custom Github Action that can be used to automaticly populate docs from action/workflow definitions.

<!-- start -->
## Github action - Autodoc
Update readme with workflow and action docs.

### Required Inputs

|Input name|Description|Type|Default|
|---|---|---|---|
|**workflow_file**|Path to the workflow or action file to document<br>example workflow: `.github/workflows/plan.yaml`<br>example action: `action.yaml`<br>|string|`.github/workflows/plan.yaml`|
|**doc_file**|Path to the markdown file to update with documentation<br>example: README.md<br>|string|`README.md`|

### Optional Inputs

|Input name|Description|Type|Default|
|---|---|---|---|
|**start_token**|Token marking the start of the autodoc section<br>default value: <!-- autodoc start --><br>|string|`<!-- autodoc start -->`|
|**end_token**|Token marking the end of the autodoc section|string|`<!-- autodoc end -->`|
|**table**|Format inputs as a markdown table|string|`true`|
|**debug**|Print debug messages. 0=none, 1=some, 2=more, 3=all|string|`0`|


### Outputs

|Output name|Description|
|---|---|
|file_type|The type automaticly detected by the script of the input_file documented: workflow or action|
|autodoc_out|If enabled, the generated documentation for inputs, secrets, and outputs|

### Simple example usage

```yaml
---
name: Example Workflow using this Action
on:
  pull_request:

jobs:
  example-job:
    name: Example Job
    steps:
      - uses: actions/checkout@v7.0.1
        with:
          ref: ${{ github.head_ref }}
          persist-credentials: false

      - name: example-step
        uses: nrkno/github-action-action-workflow-autodoc@v2
        with:
          workflow_file: .github/workflows/plan.yaml
          doc_file: README.md

      # Commit the changed file in a separate git-only step that alone
      # receives a token. Never hand write credentials to this action.
```

## Lockfile upkeep

`.github/workflows/actions.lock` is generated by the
[`gh actions-lock`](https://github.com/github/gh-actions-lock) extension. Step
`uses:` references keep full version tags (`actions/checkout@v7.0.1`); the
lockfile records the commit SHA each tag resolved to, including transitive
actions, and GitHub enforces those SHAs when the workflow runs. A moved or
re-pointed tag therefore cannot change what runs. Whenever a `uses:` reference
in `.github/workflows/` is added, removed or changed, update the lockfile in the
same PR:

```sh
gh extension install github/gh-actions-lock --pin v0.4.1  # once
gh actions-lock
```

Commit `actions.lock` together with any tag rewrite the extension makes.
Renovate regenerates the lockfile in its action-bump PRs; run the command above for hand edits.

Reusable workflow calls (`jobs.<job_id>.uses`) are not covered by the lockfile.
Keep them pinned to a full commit SHA with a `# vX.Y.Z` comment.
The `Actions lockfile` workflow runs `gh actions-lock --verify-local` on PRs that
touch `.github/workflows/` and fails if an action reference has no lockfile
entry. Do not edit the lockfile by hand.

## Releases and the image

`action.yaml` builds the action image from the `Dockerfile` at the action ref, so
a pinned ref (tag or SHA) always runs exactly the code at that ref, on a
digest-pinned `python` base image. No image is published to a registry. The
release job only creates the exact tag and a GitHub release, with a
lockfile-pinned toolchain (`npm ci --ignore-scripts`). A separate `alias-tags`
job (`contents: write` only) then moves `v<major>` and `v<major>.<minor>`. `fix(deps)` commits (Renovate action and
base-image bumps) release a patch.
